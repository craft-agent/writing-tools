# 改稿のルール

`compare` が報告する、改稿で変わったものの解説です。数、名前、内容語、義務・推量・強調の語、文頭の接続語と指示語、文末を扱います。指摘ごとの `reference` は、このファイルの見出しを指します。見出しはルールの id そのものです。

`compare` は、改稿した文章(`text`)を、元の文章(`original`)と照らして読みます。書き直しの途中で、数や名前が黙って消えたり、「べきです」が「かもしれません」に変わったりしていないかを確かめるためです。1 つの文章を診断する `inspect` とは別の呼び出しで、`checks` は取りません。`compare` が走らせるのは、`revision` チェックだけです。

このチェックには、ルールが順に加わります。いまあるのは、次の 11 のルールです。

| ルール                | 重大度     | 報告すること                                           |
| --------------------- | ---------- | ------------------------------------------------------ |
| `number_lost`         | `critical` | 元にあった数が、改稿で減った                           |
| `number_added`        | `warn`     | 元になかった数が、改稿で増えた                         |
| `name_lost`           | `critical` | 元にあった名前が、改稿で減った                         |
| `name_added`          | `warn`     | 元になかった名前が、改稿で増えた                       |
| `content_word_lost`   | `info`     | 元にあった内容語が、改稿で減った(エンジンが要る)       |
| `content_word_added`  | `info`     | 元になかった内容語が、改稿で増えた(エンジンが要る)     |
| `obligation_changed`  | `warn`     | 義務を表す語が、対の文で減った、または増えた           |
| `conjecture_changed`  | `warn`     | 推量を表す語が、対の文で減った、または増えた           |
| `emphasis_changed`    | `warn`     | 強調を表す語が、対の文で減った、または増えた           |
| `lead_changed`        | `info`     | 文頭の接続語や指示語が、対の文で変わった               |
| `stance_ending_moved` | `warn`     | 文末が、`stance` に反する種類へ動いた(`stance` が要る) |

消えた数や名前は `critical` です。読み手は、元の文章にあった事実を失います。増えたものと、義務・推量・強調の語が変わったこと、文末が `stance` に反して動いたことは `warn` です。読み手は、それを書き手が改稿で言い切ったこと、あるいは言い切るのをやめたことだと受け取ります。内容語と文頭の語は `info` です。内容語は、言い換えで入れ替わるのが普通で、欠落か言い換えかは、文脈を知る書き手にしか判断できません。文頭の語は、つながり方が変わったことを、書き手が確かめるための知らせです。書き手が意図して変えたのなら、そのままで構いません。意図していなければ、直す合図です。内容語の 2 つのルールだけは、形態素解析のエンジンが要ります(次の「内容語」の節)。ほかのルールは、エンジンなしで、既定で動きます。`stance_ending_moved` は、`stance` を渡した呼び出しでしか動かず、渡さなかったときも `not_run` には載りません。

## 2 つの文章と、文の対応

2 つの文章は、`inspect` と同じ読み方で読みます。コードブロック、インラインコード、URL、リンク先、引用ブロック、HTML コメント、フロントマターは、どちらでも読みません。数や名前は、本文、リストの項目、見出し、表の行から拾います。

比べる前に、2 つの文章の文を対応づけます。

1. 空白と、マスクされた部分(インラインコードなど)を除き、全角と半角の違いをそろえて、同じになる文は、順序を保ったまま対にします。折り返しの位置や、日本語と英単語のあいだの空白が違うだけでは、変わった文になりません。
2. 同じ文どうしの対のあいだに残った、変わった文は、似ているものを対にします。似ている度合いは、隣り合う 2 文字の組(文字のバイグラム)の Dice 係数で測り、0.5 以上のものを、高い順に、前後が交差しないように選びます。
3. 対にならなかった文は、元から消えた文、または改稿で増えた文です。文を別の場所へ動かすと、順序が合わないので、元の位置では消えた文、移した先では増えた文になります。

数、名前、内容語は、文ごとではなく、文章の全体で数えます。そのため、文を動かしただけなら、これらの指摘は出ません。

義務・推量・強調の語、文頭の語、文末は、対になった文のなかで比べます。変わらない対は、同じ文なので読みません。対にならなかった文は、相手がないので、その文にある語のすべてが、元なら消えたもの、改稿なら増えたものです。こうして、ある文で消えた語と、別の文で増えた語は、打ち消し合わず、2 つの変更として報告します。

ただし、文を動かしただけなら、報告しません。対にならなかった文が、元と改稿の両方にあり、空白や幅の違いを除いて同じ文なら、動かした文です。同じ文が何度もあれば、順に対応させます。動かして、さらに書き換えた文は、似た文として対にならない限り、元で消えて改稿で増えたものとして読みます。

指摘の位置は、次のとおりです。

- `line` と `column` は、いつも改稿の位置です。消えたものは、改稿で本来あった場所を指します。元の文と対になった改稿の文の先頭です。その文が対にならなければ、次に対のある文の先頭、そのあとに対のある文がなければ、改稿の末尾です。
- `original_line` と `original_column` は、元の文章の位置です。消えたものにつきます。増えたものは、元に場所がないので、つきません。文頭の語と文末は、対になった文があるので、増えたときも、元の文の位置がつきます。
- `excerpt` は、変わったものがある文章から取ります。消えたものは元から、増えたものと変わったものは改稿からです。

同じ数や名前が何度も出てくるときは、減った回数だけ、あるいは増えた回数だけを指摘します(内容語は、語ごとに 1 件です。「内容語」の節を見てください)。どの使い方を指すかは、対にならなかった文、変わった文、変わらない文の順に選び、同じなら後ろの使い方を選びます。

## 数

数は、値で比べます。`1,000` と `１０００` と `千円` の千は、どれも 1000 で、同じ数です。次のものを、数として読みます。

- 半角と全角の数字。コンマの区切り(`1,000` `１，０００`)と小数(`3.5`)も含みます。
- 漢数字(`〇` `一` `二` `三` `四` `五` `六` `七` `八` `九` `十` `百` `千` `万` `億` `兆`)の並び。ただし、あとに単位や助数詞が続くときだけです。`円` `年` `月` `日` `時` `分` `秒` `人` `件` `個` `回` `本` `枚` `台` `倍` `割` `歳` `%` `度` `点` `位` `番` `階` `冊` `社` `名` `週` `か月` などが続きます。
- 数字のあとの `十` `百` `千` `万` `億` `兆`。`3万` は 30000 です。単位がなくても数です。

漢数字の値は、計算します。`三千五百万` は 35000000、`二〇二六` は 2026 です(位取りではなく、数字を 1 つずつ読みます)。日付と時刻は、書かれている数字ごとの数です。`2026年11月27日` は、2026、11、27 です。小数の末尾の 0 と、整数の先頭の 0 は、値に影響しません。`3.50` は 3.5、`007` は 7 です。

数えないもの:

- `一般` `統一` `一部` `一緒` のように、語のなかにある漢数字。単位や助数詞が続かないので、数ではありません。`一番`(いちばん)と `十分`(じゅうぶん)も、語として読みます。`十分間` と `二十分` は、時間の数です。`同一` `唯一` `単一` `均一` の `一` も、数ではありません。
- `HTTP2` `A4` `iPhone15` のように、英単語や型番にくっついた数字。
- マスクされたもの。インラインコード、コードブロック、URL、リンク先のなかの数は、読みません。
- 引用ブロックの数。

### `number_lost`

元にあった数が、改稿で減っています。数は、金額、日付、件数、バージョンのように、読み手が行動を決める事実です。黙って消えると、読み手は気づけません。

```text
元: 価格は30円です。送料は500円です。
改稿: 価格は20円です。送料は無料です。
```

`30` と `500` が、改稿から消えています。`number_lost` が 2 件出ます。理由は、`"30" is in the original but not in the revision` のように、数を値で示します。元で漢数字で書かれていたときは、`"35000000" (written 三千五百万)` のように、書き方も添えます。指摘の範囲は、数の部分だけで、単位は含みません。

数えないもの: 上に挙げた、数ではないものです。

直し方: 数を消したのが意図したことかを確かめます。消すつもりがなかったなら、元の数を戻します。数を変えたのなら、新しい数が `number_added` にも出るので、両方を見て、意図した変更かを確かめます。

### `number_added`

元になかった数が、改稿で増えています。読み手は、増えた数を、書き手が確かめた事実として読みます。

```text
元: 参加者が集まりました。
改稿: 参加者が120人集まりました。
```

`120` が増えています。理由は、`"120" is in the revision but not in the original` です。増えたものには、元に場所がないので、`original_line` と `original_column` はつきません。

数えないもの: `number_lost` と同じです。

直し方: 意図して加えた数なら、そのままで構いません。根拠のない数が混ざったのなら、削るか、出典を確かめます。

## 名前

名前は、`terms` の一覧と同じ見つけ方で拾います。略語(`API` `HTTP2`)、ラテン文字の名前(`GitHub` `iOS`)、3 文字以上のカタカナ語(`サーバー`)です。`Linux` のように頭文字だけが大文字の語は、ほかの英単語と空白で隣り合っていないときだけ、名前です。英語の句は、語ごとに数えません。

比べるときの形も、`terms` と同じです。末尾の長音符 `ー` のあるなし(`サーバー` と `サーバ`)と、全角と半角の違い(`ＡＰＩ` と `API`)は、同じ名前です。表記の揺れは `notation` が見るので、ここでは変更に数えません。

数えないもの: 英語の句にある語、コードやリンク先、引用ブロックにある名前です。固有名詞でも、日本語のものは、形態素解析がないと見分けられないので、数えません。

### `name_lost`

元にあった名前が、改稿で減っています。製品名、規格名、略語は、読み手が検索したり、ほかの文書と照らしたりする手がかりです。消えると、読み手は、何の話だったのかを見失います。

```text
元: API キーを GitHub に登録する。
改稿: キーを登録する。
```

`API` と `GitHub` が消えています。`name_lost` が 2 件出ます。理由は、`"API" is in the original but not in the revision` のように、元の書き方で示します。

数えないもの: 上に挙げた、名前ではないものです。

直し方: 名前を消したのが意図したことかを確かめます。説明を短くしただけなら、名前は残して、読み手が手がかりを保てるようにします。別の名前へ置き換えたのなら、新しい名前が `name_added` にも出ます。

### `name_added`

元になかった名前が、改稿で増えています。読み手は、増えた名前を、書き手が確かめたうえで入れたものと受け取ります。

```text
元: 保存先を選べます。
改稿: 保存先を GitHub から選べます。
```

`GitHub` が増えています。理由は、`"GitHub" is in the revision but not in the original` です。確かめていない名前を、勢いで足していないかを、見直します。

数えないもの: `name_lost` と同じです。

直し方: 意図して加えた名前なら、そのままで構いません。本文の事実として確かめられていないなら、削るか、確かめてから残します。

## 内容語

内容語は、文章が何について書かれているかを担う語です。名詞、動詞、形容詞、副詞を、形態素解析で拾います。「古いデータ」を「データ」に直すと、数も名前も変わらないまま、`古い` という条件が黙って消えます。数や名前では拾えないこうした変更を、内容語で拾います。

次の 2 つのルールは、形態素解析で文を語に分けて調べます。

形態素解析のエンジンは、パッケージのコマンドライン(`writing-tools-cli engine install`)で一度入れます。入れていないときや、エンジンが動かなかったときは、この 2 つは `not_run` に載り、内容語については何も言いません。「指摘がない」ことと「調べていない」ことは別なので、`not_run` を確認してください。数、名前、義務・推量・強調の語、文頭の語、文末のルールは、エンジンがなくても動きます。エンジンは、元と改稿を合わせて 1 回だけ呼びます。

段落が長すぎてエンジンが読まなかったときは、その段落の行が `not_run` に出ます。元の文章の段落なら、その項目に `text: "original"` がつきます。内容語は、2 つの文章の全体を読めたときにしか比べられません。一部を読めないまま数えると、読めた側の語が、すべて変わったものに見えてしまうからです。そのため、どちらかに読めない段落があるときは、この 2 つのルールは何も報告しません。

読むのは、本文とリストの項目の語です。見出し、表の行、引用ブロックは、エンジンに送らないので読みません。インラインコードや URL のようにマスクされた部分も、語としては読みません。

語は、形態素解析の正規形で数えます。`閉じた` `閉じて` `閉じる` は、どれも `閉じる` です。`行なう` と `行う`、`出来る` と `できる` のように、書き方だけが違う語も、同じ語です。表記の揺れは `notation` が見るので、ここでは変更に数えません。幅の違いも、そろえて数えます。数え方は、数や名前と同じく、文章の全体です。元と改稿で、語ごとの数を比べ、多いほうの差の分が、消えた語、または増えた語です。文を動かしただけなら、数は変わりません。どの使い方を指すかは、数と同じです。

数や名前と違うのは、報告のまとめ方です。数や名前は、使い方ごとに 1 件ずつ報告します。内容語は、1 つの文を書き換えると、多くの語が一度に変わるので、語ごとに 1 件にまとめます。差が 2 回以上のときは、理由の末尾に `(2 uses)` のように回数がつきます。位置は、指す使い方のうち、いちばん前のものです。

数えないもの:

- 数。数字、漢数字の数詞です。`number_lost` と `number_added` が報告します。
- 名前と、名前の中にある語。略語、ラテン文字の名前、3 文字以上のカタカナ語です。`name_lost` と `name_added` が報告します。
- 代名詞(`これ` `それ`)と、ほかの語を支えるだけの動詞や名詞(`〜している` の `いる`、`〜してしまう` の `しまう` など)。形態素解析が、それと判断した語です。
- 助詞、助動詞、記号、接続詞、連体詞、形状詞(`簡単` `重要` のような、「な」で名詞につながる語)。
- どの文章にも出てきて、増減しても内容が変わらない、ごく一般的な語。`する` `ある` `いる` `なる` `できる` `こと` `もの` `よう` `ため` `とき` `ところ` `わけ` `はず` `ほう`。漢字で書いても(`為る` `有る` `事` `物` `様` `為` `時` `所` `訳` `方`)同じ語として扱います。`前` と `後` は、この中に入れていません。「削除する前に」と「削除した後に」は、順序が逆になるので、変更として拾います。

言い換えは、語を入れ替えるので、このルールに出ます。`保存してから` を `保存した後に` に変えると、`後` が増えたと報告します。同じ意味でも、書き手が確かめるための知らせとして、`info` にしています。

### `content_word_lost`

元にあった内容語が、改稿で減っています。語は、条件、対象、方法のように、文の範囲や意味を絞る役を持つことがあります。消えると、読み手は、元の文が絞っていた範囲を知ることができません。

```text
元: 古いデータは削除されます。
改稿: データは削除されます。
```

`古い` が消えています。理由は、`"古い" is in the original but not in the revision` です。活用した語や書き方の違う語は、正規形で示し、書かれていた形が違うときは、`"閉じる" (written 閉じ) is in the original but not in the revision` のように添えます。位置は、改稿で本来あった場所を指し、`original_line` と `original_column` が元の語を指します。`excerpt` も元から取ります。

数えないもの: 上に挙げた、内容語ではないものです。

直し方: 語を消したのが意図したことかを確かめます。短くしただけで、その語が文の範囲を絞っていたなら、戻します。別の語に言い換えたのなら、新しい語が `content_word_added` にも出るので、両方を見て、同じ意味かを確かめます。

### `content_word_added`

元になかった内容語が、改稿で増えています。読み手は、増えた語を、書き手が確かめたうえで加えた条件や対象として読みます。

```text
元: データを保存します。
改稿: 古いデータを保存します。
```

`古い` が増えています。理由は、`"古い" is in the revision but not in the original` です。増えたものには、元に場所がないので、`original_line` と `original_column` はつきません。

数えないもの: `content_word_lost` と同じです。

直し方: 意図して加えた語なら、そのままで構いません。確かめていない条件が混ざっているなら、削るか、確かめてから残します。

## 義務・推量・強調の語

文の言い切りの強さを決める語を、3 つの種類に分けて数えます。義務(守らせる)、推量(言い切らない)、強調(念を押す)です。「ログを確認すべきです」を「ログを確認します」に直すと、事実は同じでも、読み手に求める強さが変わります。数や名前と違って、語が消えたこと自体は、誤りではありません。ただ、書き手が気づかないまま強さが変わることを避けるため、`warn` で知らせます。

3 つのルールは、同じ仕組みで動きます。

1. 対になった文で、変わった対だけを読みます。変わらない対は、同じ文なので読みません。
2. 文ごと、種類ごとに、語を数えます。語は、下に挙げたパターンで見つけます。折り返しの改行や空白をまたいでも見つけますが、マスクされた部分(インラインコードなど)は読まず、またいで 1 つの語にもしません。
3. 元の数が多ければ、その差の分だけ、元の語を「消えた」と報告します。改稿の数が多ければ、差の分だけ、改稿の語を「増えた」と報告します。数が同じなら、語が入れ替わっていても報告しません。「べきです」が「なければなりません」になっても、義務は義務のままだからです。
4. 差のある種類で、どの語を指すかは、相手の文にない書き方の語を先に、同じなら後ろの語を選びます。

対にならなかった文は、前の節のとおり、その文にある語のすべてが消えた、または増えたものです。動かしただけの文は読みません。

指摘の位置は、消えた語なら、改稿で本来あった場所(対の文の先頭)で、`original_line` と `original_column` が元の語を指し、`excerpt` も元から取ります。増えた語なら、改稿の語の位置で、元の位置はつきません。理由は、`"べきです" (obligation) was dropped from this sentence` のように、語と種類を示します。増えたときは、`was added to this sentence` です。

3 つのルールは別の id なので、書き手は 1 つだけを `exclude_rules` で外せます。

パターンは、別の語の一部に当たらないように、後ろや前の文字を絞っています。それぞれの種類の「数えないもの」に挙げたものが、その例です。

### `obligation_changed`

義務を表す語が、対の文で減ったか、増えています。

```text
元: ログを確認すべきです。
改稿: ログを確認します。
```

`べきです` が消えています。理由は、`"べきです" (obligation) was dropped from this sentence` です。

数える語:

- `なければ` `なくては` `ねば` のあとに、`ならない` `ならず` `なりません` `いけない` `いけません` が続く形(`なければなりません` `なくてはいけない` `ねばならない` など)。
- `ないといけない` `ないといけません`
- `べき`。あとに `である` `です` `だ` が続くときは、まとめて 1 つです。
- `必要がある` `必要があります`、`必要です` `必要だ` `必要である`
- `必須`

数えないもの: `べき乗` と `べき等` の `べき`。`必要な機能` の `必要`(あとが `な` なので、義務ではなく性質です)。`必要がありません` と `不必要です`(必要がないという意味です)。`必須ではない` と `必須ではありません`。

直し方: 義務を弱めたのが意図したことかを確かめます。規則や手順で、守らせるつもりだったなら、元の言い方を戻します。増えたときは、書き手が本当に求めているかを確かめます。

### `conjecture_changed`

推量を表す語が、対の文で減ったか、増えています。言い切るのをやめたり、逆に、確かめていないことを言い切ったりしていないかを見ます。

```text
元: 届くはずです。
改稿: 届きます。
```

`はずです` が消えています。理由は、`"はずです" (conjecture) was dropped from this sentence` です。「届きます」と言い切るなら、根拠があるかを確かめます。

数える語:

- `でしょう` `だろう` `であろう`
- `かもしれない` `かもしれません`。`かも知れない` `かも知れません` も同じです。
- `と思われ` `と考えられ`(`と思われる` `と考えられます` など)
- `と思います` `と思う`
- `はずだ` `はずです` `はずである` `はずがない` `はずがありません`
- `おそらく` `恐らく` `たぶん` `多分`
- `らしい`。ただし、動詞の語尾(`行く` `来る`)、`た`、`ない` のあとだけです。
- `ようだ` `ようです` `ようである` `ようだった` `ようでした`
- `可能性がある` `可能性があります` `可能性が高い` `可能性が低い`(`が` は `も` と `は` でも同じです)

数えないもの: `はずす` のように、`はず` のあとが `だ` `です` `である` でないもの。`ように`(`届くように送る`)。`多分に` `多分の` `多分な` `多分野` の `多分`。`ようでしたら` の `ようでした`。`彼らしい` `かわいらしい` `素晴らしい` `あたらしい` の `らしい`(推量ではなく、性質や別の語です)と、`らしく` `らしさ`。

`ようだ` と `ようです` は、たとえの `夢のようです` も数えます。推量とたとえは、語の形では見分けられないからです。たとえが増えたり消えたりしても、同じように報告するので、意図したことなら、そのままで構いません。

直し方: 推量を消したのなら、言い切れる根拠が改稿の文章にあるかを確かめます。増えたのなら、言い切っていた内容を、確かめられていないものに弱めたことになります。意図していたかを確かめます。

### `emphasis_changed`

強調を表す語が、対の文で減ったか、増えています。強調は、読み手に念を押す語です。消えれば、念押しが失われ、増えれば、改稿者が強く言い切ったと受け取られます。

```text
元: 設定ファイルの内容を必ず確認します。
改稿: 設定ファイルの内容を確認します。
```

`必ず` が消えています。理由は、`"必ず" (emphasis) was dropped from this sentence` です。

数える語:

- `必ず` `かならず`
- `絶対`(あとに `に` が続けば、まとめて 1 つです)
- `常に` `つねに`
- `決して`
- `まさに`
- `こそ`
- `非常に`
- `きわめて` `極めて`
- `確実に`
- `明らかに` `あきらかに`

数えないもの: `必ずしも`(逆の意味です)。`絶対値` `絶対パス` `絶対評価` のように、漢字やカタカナが続く `絶対`。漢字のあとにある `常に` と `決して`(`正常に` `日常に` `解決して`)。`非常に` は、別の語として数えます。`どこそこ` `こそこそ` `こそあど` の `こそ`。`極めている` `極めて、` のように、動詞の `極める` の形。`不確実に` の `確実に`。`明らかにする` `明らかにした` `明らかになった` `明らかにされた` の `明らかに`(「はっきりさせる」の意味です)。

直し方: 強調を消したのが意図したことかを確かめます。念を押す必要があるのは、読み手が間違えると困る箇所です。強調が増えたときは、その箇所が本当に念を押すべき箇所かを見ます。強調の語が多い文章は、どれも目立たなくなります。

## 文頭の語

### `lead_changed`

文の頭にある接続語や指示語が、対の文で変わっています。接続語は、前の文との関係を示します。「しかし」を「また」に変えると、逆接が並列になり、文章の論理が変わります。指示語を落とすと、何を指していたかが読み取れなくなります。

```text
元: しかし、ログを確認します。
改稿: また、ログを確認します。
```

`しかし` が `また` に変わっています。理由は、`The leading "しかし" was changed to "また"` です。語が加わったときは `A leading "また" was added to this sentence`、消えたときは `The leading "しかし" was dropped from this sentence` です。

読むのは、変わった対だけです。対にならなかった文は、比べる相手がないので読みません。変わらない対は、頭の語も同じです。語の違いだけを見るので、同じ語なら、その後ろが変わっていても報告しません。`一方で` と `一方、` は、どちらも `一方` と読むので、同じ語です。

文頭の語は、文の先頭から、空白と開きかっこ(`「` など)を飛ばした位置で、見つけます。接続語は、次の語です。

- `しかしながら` `しかし` `ところが` `ところで` `そして` `そうして` `こうして` `それから` `それに` `それでも` `それでは` `それで` `それとも`
- `だから` `ですから` `したがって` `そのため` `このため` `そのうえ` `その結果` `そこで` `このように` `そのように`
- `さらに` `なぜなら` `つまり` `すなわち` `他方` `次に` `最初に` `最後に` `ただし` `なおかつ` `しかも` `ですが` `だが` `けれども` `けれど` `だけど` `とはいえ`
- `加えて` `逆に` `反対に` `同様に` `要するに` `結局` `例えば` `たとえば` `ちなみに` `あるいは` `もしくは` `または` `よって` `ゆえに` `さて`
- `また`(あとが `ぎ` `が` `の` `も` のときを除く)
- `一方`(あとが `、` か `で` のとき)
- `もっとも` `では` `でも`(あとが `、` のとき)
- `ただ`(あとが `の` のときを除く)、`なお`(あとが `の` `も` のときを除く)、`まず`。この 3 語は、あとに読点、助詞、漢字、カタカナ、英数字が続くときだけです。

指示語は、次の語です。

- `これら` `それら` `あれら` `こうした` `そうした` `こういった` `そういった` `このような` `そのような` `こんな` `そんな` `あんな`
- `これ` `それ` `あれ` `この` `あの` `ここ` `そこ` `その`。あとに読点、助詞、漢字、カタカナ、英数字が続くときだけです。`その` は `その他` を除きます。
- `こう` `そう`。あとに読点、漢字、カタカナが続くときだけです。

数えないもの: `それぞれ` `今` `ただの` `まずい` `一方的` のように、別の語の始まり。`そうです` のように、助詞だけが続く `そう`。`その他`。マスクされた部分から始まる文。

接続語を、同じ意味の別の表記(`例えば` と `たとえば`)に変えたときも、変わったものとして報告します。

直し方: つながりが変わったのが意図したことかを確かめます。接続語を変えたなら、前後の文の関係も、それに合うかを見ます。落としたなら、前の文との関係が、語がなくても伝わるかを見ます。

## 文末

### `stance_ending_moved`

文末が、`stance` に反する種類へ動いています。`stance` を渡した呼び出しでだけ動くルールで、渡さなかったときは動かず、`not_run` にも載りません。`stance` は、文章の文末が、何であるべきかを示します。助言(`advice`)、規則(`rule`)、説明(`explanation`)の 3 つです。`inspect` の `stance_ending` が、文章に残る反する文末を拾うのに対して、このルールは、改稿が反する方向へ動かした文末だけを拾います。

```text
元: ログを確認します。
改稿: ログを確認してください。
stance: explanation
```

説明(`explanation`)の文章で、文末が依頼(`てください`)になりました。理由は、`a request in an explanation: the sentence now ends in "てください"; the original's ending was not a request` です。

文末の種類は、`stance_ending` と同じ表で読みます。種類ごとに、助言、規則、説明が避ける種類は、次のとおりです。

| `stance`      | 反する文末の種類         |
| ------------- | ------------------------ |
| `advice`      | 動作(`〜します`)         |
| `rule`        | 推奨、評価(`重要です`)   |
| `explanation` | 推奨(`〜ましょう`)、依頼 |

報告するのは、変わった対のうち、改稿の文末が反する種類で、元の文末が別の種類だったときです。元が同じ種類なら、改稿が動かしたのではないので、報告しません。変わらない対は、読みません。対にならなかった改稿の文は、`inspect` の `stance_ending` が見るので、`compare` では読みません。文末のない文(終止の記号がない文)、見出し、引用は、読みません。

`stance_ending` は、説明の文章の最後の文が依頼や推奨で終わるのを許します。このルールは、許しません。最後の文でも、改稿が動かしたことが報告の対象だからです。

位置は、改稿の文末(文末の語から、終止の記号まで)で、`original_line` と `original_column` が、元の文の文末を指します。元の文に分類できる文末がなければ、元の終止の記号の位置、終止の記号もなければ、文の終わりです。`excerpt` は改稿から取ります。

直し方: 文末を動かしたのが意図したことかを確かめます。説明の文章に依頼が混ざったのなら、文章の立場が変わっています。立場を変えるつもりなら、`stance` の値を変えて見直します。変えないなら、文末を元の種類に戻します。
