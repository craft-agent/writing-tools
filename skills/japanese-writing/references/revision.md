# 改稿のルール

`compare` が報告する、改稿で変わった数と名前の解説です。指摘ごとの `reference` は、このファイルの見出しを指します。見出しはルールの id そのものです。

`compare` は、改稿した文章(`text`)を、元の文章(`original`)と照らして読みます。書き直しの途中で、数や名前が黙って消えたり、増えたりしていないかを確かめるためです。1 つの文章を診断する `inspect` とは別の呼び出しで、`checks` は取りません。`compare` が走らせるのは、`revision` チェックだけです。

このチェックには、ルールが順に加わります。いまあるのは、数と名前の 4 つです。

| ルール         | 重大度     | 報告すること                     |
| -------------- | ---------- | -------------------------------- |
| `number_lost`  | `critical` | 元にあった数が、改稿で減った     |
| `number_added` | `warn`     | 元になかった数が、改稿で増えた   |
| `name_lost`    | `critical` | 元にあった名前が、改稿で減った   |
| `name_added`   | `warn`     | 元になかった名前が、改稿で増えた |

消えた数や名前は `critical` です。読み手は、元の文章にあった事実を失います。増えたものは `warn` です。読み手は、それを書き手が改稿で言い切ったことだと受け取ります。書き手が意図して変えたのなら、そのままで構いません。意図していなければ、直す合図です。どのルールも、形態素解析のエンジンは要らず、既定で動きます。

## 2 つの文章と、文の対応

2 つの文章は、`inspect` と同じ読み方で読みます。コードブロック、インラインコード、URL、リンク先、引用ブロック、HTML コメント、フロントマターは、どちらでも読みません。数や名前は、本文、リストの項目、見出し、表の行から拾います。

比べる前に、2 つの文章の文を対応づけます。

1. 空白と、マスクされた部分(インラインコードなど)を除き、全角と半角の違いをそろえて、同じになる文は、順序を保ったまま対にします。折り返しの位置や、日本語と英単語のあいだの空白が違うだけでは、変わった文になりません。
2. 同じ文どうしの対のあいだに残った、変わった文は、似ているものを対にします。似ている度合いは、隣り合う 2 文字の組(文字のバイグラム)の Dice 係数で測り、0.5 以上のものを、高い順に、前後が交差しないように選びます。
3. 対にならなかった文は、元から消えた文、または改稿で増えた文です。文を別の場所へ動かすと、順序が合わないので、元の位置では消えた文、移した先では増えた文になります。

数と名前は、文ごとではなく、文章の全体で数えます。そのため、文を動かしただけなら、数と名前の指摘は出ません。

指摘の位置は、次のとおりです。

- `line` と `column` は、いつも改稿の位置です。消えたものは、改稿で本来あった場所を指します。元の文と対になった改稿の文の先頭です。その文が対にならなければ、次に対のある文の先頭、そのあとに対のある文がなければ、改稿の末尾です。
- `original_line` と `original_column` は、元の文章の位置です。消えたものにつきます。増えたものは、元に場所がないので、つきません。
- `excerpt` は、変わったものがある文章から取ります。消えたものは元から、増えたものは改稿からです。

同じ数や名前が何度も出てくるときは、減った回数だけ、あるいは増えた回数だけを指摘します。どの使い方を指すかは、対にならなかった文、変わった文、変わらない文の順に選び、同じなら後ろの使い方を選びます。

## 数

数は、値で比べます。`1,000` と `１０００` と `千円` の千は、どれも 1000 で、同じ数です。次のものを、数として読みます。

- 半角と全角の数字。コンマの区切り(`1,000` `１，０００`)と小数(`3.5`)も含みます。
- 漢数字(`〇` `一` `二` `三` `四` `五` `六` `七` `八` `九` `十` `百` `千` `万` `億` `兆`)の並び。ただし、あとに単位や助数詞が続くときだけです。`円` `年` `月` `日` `時` `分` `秒` `人` `件` `個` `回` `本` `枚` `台` `倍` `割` `歳` `%` `度` `点` `位` `番` `階` `冊` `社` `名` `週` `か月` などが続きます。
- 数字のあとの `十` `百` `千` `万` `億` `兆`。`3万` は 30000 です。単位がなくても数です。

漢数字の値は、計算します。`三千五百万` は 35000000、`二〇二六` は 2026 です(位取りではなく、数字を 1 つずつ読みます)。日付と時刻は、書かれている数字ごとの数です。`2026年11月27日` は、2026、11、27 です。小数の末尾の 0 と、整数の先頭の 0 は、値に影響しません。`3.50` は 3.5、`007` は 7 です。

数えないもの:

- `一般` `統一` `一部` `一緒` のように、語のなかにある漢数字。単位や助数詞が続かないので、数ではありません。`一番`(いちばん)と `十分`(じゅうぶん)も、語として読みます。`十分間` と `二十分` は、時間の数です。`同一` `唯一` `単一` `均一` の `一` も、数ではありません。
- `HTTP2` `A4` `iPhone15` のように、英単語や型番にくっついた数字。
- マスクされたもの。インラインコード、コードブロック、URL、リンク先のなかの数は、読みません。
- 引用ブロックの数。

### `number_lost`

元にあった数が、改稿で減っています。数は、金額、日付、件数、バージョンのように、読み手が行動を決める事実です。黙って消えると、読み手は気づけません。

```text
元: 価格は30円です。送料は500円です。
改稿: 価格は20円です。送料は無料です。
```

`30` と `500` が、改稿から消えています。`number_lost` が 2 件出ます。理由は、`"30" is in the original but not in the revision` のように、数を値で示します。元で漢数字で書かれていたときは、`"35000000" (written 三千五百万)` のように、書き方も添えます。指摘の範囲は、数の部分だけで、単位は含みません。

数えないもの: 上に挙げた、数ではないものです。

直し方: 数を消したのが意図したことかを確かめます。消すつもりがなかったなら、元の数を戻します。数を変えたのなら、新しい数が `number_added` にも出るので、両方を見て、意図した変更かを確かめます。

### `number_added`

元になかった数が、改稿で増えています。読み手は、増えた数を、書き手が確かめた事実として読みます。

```text
元: 参加者が集まりました。
改稿: 参加者が120人集まりました。
```

`120` が増えています。理由は、`"120" is in the revision but not in the original` です。増えたものには、元に場所がないので、`original_line` と `original_column` はつきません。

数えないもの: `number_lost` と同じです。

直し方: 意図して加えた数なら、そのままで構いません。根拠のない数が混ざったのなら、削るか、出典を確かめます。

## 名前

名前は、`terms` の一覧と同じ見つけ方で拾います。略語(`API` `HTTP2`)、ラテン文字の名前(`GitHub` `iOS`)、3 文字以上のカタカナ語(`サーバー`)です。`Linux` のように頭文字だけが大文字の語は、ほかの英単語と空白で隣り合っていないときだけ、名前です。英語の句は、語ごとに数えません。

比べるときの形も、`terms` と同じです。末尾の長音符 `ー` のあるなし(`サーバー` と `サーバ`)と、全角と半角の違い(`ＡＰＩ` と `API`)は、同じ名前です。表記の揺れは `notation` が見るので、ここでは変更に数えません。

数えないもの: 英語の句にある語、コードやリンク先、引用ブロックにある名前です。固有名詞でも、日本語のものは、形態素解析がないと見分けられないので、数えません。

### `name_lost`

元にあった名前が、改稿で減っています。製品名、規格名、略語は、読み手が検索したり、ほかの文書と照らしたりする手がかりです。消えると、読み手は、何の話だったのかを見失います。

```text
元: API キーを GitHub に登録する。
改稿: キーを登録する。
```

`API` と `GitHub` が消えています。`name_lost` が 2 件出ます。理由は、`"API" is in the original but not in the revision` のように、元の書き方で示します。

数えないもの: 上に挙げた、名前ではないものです。

直し方: 名前を消したのが意図したことかを確かめます。説明を短くしただけなら、名前は残して、読み手が手がかりを保てるようにします。別の名前へ置き換えたのなら、新しい名前が `name_added` にも出ます。

### `name_added`

元になかった名前が、改稿で増えています。読み手は、増えた名前を、書き手が確かめたうえで入れたものと受け取ります。

```text
元: 保存先を選べます。
改稿: 保存先を GitHub から選べます。
```

`GitHub` が増えています。理由は、`"GitHub" is in the revision but not in the original` です。確かめていない名前を、勢いで足していないかを、見直します。

数えないもの: `name_lost` と同じです。

直し方: 意図して加えた名前なら、そのままで構いません。本文の事実として確かめられていないなら、削るか、確かめてから残します。
