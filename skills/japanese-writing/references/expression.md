# 表現のルール

`expression` チェックが報告する、文体と言い回しの解説です。指摘ごとの `reference` は、このファイルの見出しを指します。見出しはルールの id そのものです。

このチェックには、ルールが順に加わります。規約を扱うルールの考え方(指定があればそれに従い、なければ文書の多数派に合わせる)は、[notation.md](notation.md) の「基本の考え方」と同じです。読まない箇所も同じで、コードブロック、インラインコード、URL、リンク先、HTML コメント、フロントマターと、引用ブロックを読みません。

## 文体

### `register`

本文の文末を、です・ます(丁寧体)で書くか、だ・である(常体)で書くかの規約です。

| 値       | 例                   |
| -------- | -------------------- |
| `polite` | `手順を確認します。` |
| `plain`  | `手順を確認する。`   |

本文と、リストの項目にある文のうち、`。` `！` `？` `．` `!` `?` で終わる文を 1 文ずつ数えます。見出し、表、引用ブロック、コードは数えません。指摘の範囲は、語尾から終端の記号までです。

語尾は、文の終端記号の手前を読んで決めます。次のものは、語尾の後ろにあっても無いものとして扱います。

- 強調の `*` と `_`、空白
- 閉じ括弧(`」` `』` `）` `)` `]`)
- 文末の括弧書き(`（注）`、`(補足)`)

丁寧体は、次の語尾のどれかで終わる文です。続けて `か` `ね` `よ` `よね` が付いていてもかまいません。

`です` `ます` `ません` `ました` `でした` `ましょう` `ませんでした` `ください` `下さい` `でしょう`

```text
手順を確認します。
次の画面で設定を開いてください。
これで問題ないでしょうね。
```

常体は、次のどれかで終わる文です。

- `だ` `である` `だった` `であった` `ではない` `でない` `だろう`(続けて `か` `ね` `よ` が付いていてもかまいません)
- `る` `う` `く` `す` `つ` `ぬ` `ぶ` `む` `ぐ` `た` `い` のどれか 1 文字

```text
手順を確認する。
この設定は必須である。
次の画面で設定を開く。
```

丁寧体の語尾を先に調べます。`でした` や `ください` は `た` や `い` でも終わりますが、常体とは数えません。

数えないもの:

- 体言止め(`確認手順の一覧。`)や、助詞で終わる文(`確認しますが。`)。どちらの文体とも決められません。
- 終端の記号がないリストの項目(`- 設定を開く` のような箇条書き)。名詞句や、語尾を省いた書き方が多いからです。
- 引用ブロックと、見出し、表。
- 句点だけの行。

「」の中の句点は、文を終わらせません。`彼は「確認します。」と言った。` は 1 文で、数えるのは外側の語尾(`言った`)です。逆に、文が閉じ括弧で終わるときは括弧を外して語尾を読むので、`彼は「確認します」。` は `確認します` で、丁寧体と数えます。そのため、かぎ括弧で閉じる会話文が多い文書では、会話文の文体も地の文と一緒に数えられます。

指定がないときは、文書で多いほうに合わせ、少ないほうの文を 1 文ずつ指摘します。同数のときは、先に現れた文体を多いほうとみなします。丁寧体だけ、常体だけの文書は指摘しません。

直し方: 本文は、文体を 1 つにそろえます。どちらにするかは、読者と文書の種類で決めます。設定または引数の `register` で決めておくと、外れた文が 1 文ずつ指摘されます。引用やセリフなど、意図して文体を変えている文は、引用ブロックにするか、そのままにして構いません。

## 書式

### `bold_not_rendered`

`**` で囲んだ強調が、太字にならず、`**` の記号のまま表示される書き方です。重大度は `critical` です。どの読み手にも崩れて見えるので、意図した書き方ではありません。

CommonMark と GFM では、`**` の並びは、次の条件を満たすときだけ強調の始まりや終わりになります。

- **始まり**: 直後が空白ではないこと。直後が記号(句読点、括弧、`` ` `` など)のときは、直前が空白、記号、行頭のどれかであること。
- **終わり**: 直前が空白ではないこと。直前が記号のときは、直後が空白、記号、行末のどれかであること。

記号は、Unicode の句読点(`、` `。` `「` `」` など)と、記号類(`+` `→` `` ` `` など)です。日本語は語のあいだに空白を置かないため、`**` の内側が括弧や句点で外側が文字のとき、この条件に外れます。

| 太字にならない書き方                       | 直した書き方                               |
| ------------------------------------------ | ------------------------------------------ |
| `次に**「文書の立場」**を決めます。`       | `次に「**文書の立場**」を決めます。`       |
| `これは**必須です。**詳しくは後述します。` | `これは**必須です**。詳しくは後述します。` |
| ``a**`code`**b``                           | ``a **`code`** b``                         |

括弧と句読点は、`**` の外に出します。外に出せないとき(インラインコードを強調する場合など)は、`**` の外側に半角空白を入れます。

太字になる書き方は、指摘しません。`**語**を` や `これは**大事**な点です。` は、内側が文字なので、日本語のすぐ隣でも太字になります。

指摘の範囲は、対の最初の `**` から最後の `**` までです。1 行のなかの `**` を、先頭から 2 つずつ対にして調べます。

数えないもの:

- インラインコードやコードブロックの中の `**`、引用ブロック。
- バックスラッシュで打ち消した `\*\*`。
- 並びが 2 つではない `*`(`*強調*` や `***`)。
- 行をまたぐ強調と、相手のない `**`。

直し方: 指摘の理由に、移すとよい記号が出ます。括弧や句読点を `**` の外に出すか、`**` の外側に空白を入れます。内側に空白があるときは、その空白を除きます。

### `bold_density`

太字が多く、どれも目立たなくなっている文書です。重大度は `info` で、強調を意図して多く付けている文書では、書き手が判断して構いません。

本文、見出し、リスト、表の文字(空白を除く)1,000 字あたりに、実際に太字になる `**…**` がいくつあるかを数えます。太字にならない `**` は `bold_not_rendered` が扱うので、数えません。

| ジャンル                      | 指摘する率                  |
| ----------------------------- | --------------------------- |
| `general` `technical` `essay` | 1,000 字あたり 3.0 を超える |
| `business`                    | 1,000 字あたり 5.0 を超える |

読める文字が 300 字以下の文書は、率が安定しないので調べません。指摘は文書に 1 件で、最初の太字を示します。理由に、太字の数、文字数、率が出ます。

数えないもの: コードブロックと引用ブロックの文字、コードの中の `**`。インラインコードの文字は、1 文字ずつ文字数に入ります。

直し方: 読み手に必ず覚えてほしい語や警告だけを残し、ほかは外します。用語の初出や注意書きなど、意図して付けている太字なら、そのままで構いません。

### `list_density`

箇条書きが多く、文章としてのつながりが薄い文書です。重大度は `info` です。`general` と `essay` でだけ調べます。`technical` と `business` は、手順や項目の列挙が本来の形なので、調べません。

本文、見出し、リスト、表の空でない行のうち、リストの行(項目の続きの行を含む)が占める割合を数えます。次のすべてに当てはまるときに指摘します。

- リストの行が、全体の 40% を超える。
- 読める文字が 300 字を超える。
- 読める行が 10 行以上ある。

指摘は文書に 1 件で、最初のリストの行を示します。理由に、リストの行数、全体の行数、割合が出ます。

直し方: 並列の項目はリストのまま残し、理由や経緯、条件のつながりを説明している項目は、文章でつなぎます。項目の列挙が目的の文書なら、そのままで構いません。

## リズム

文末と文の長さのルールは、どれも `info` の目安です。並列の構造を同じ語尾で書くなど、意図して繰り返しているなら、書き手が判断して構いません。

ここで数える文は、本文(段落)の、`。` `！` `？` `．` `!` `?` で終わる文です。リスト、見出し、表、引用ブロックの文と、終端の記号がない文は数えません。

### `ending_repetition`

同じ段落で、同じ語尾の文が 3 文以上続く書き方です。

語尾は、次の一覧から、文の終端の記号の手前に当てはまる最も長いものを選びます。`でした` は `た` ではなく `でした` と読みます。閉じ括弧や強調の記号、文末の括弧書きは、`register` と同じく無いものとして扱います。

`です` `ます` `でした` `ました` `ません` `だ` `である` `だった` `た` `る`

```text
今日は定例会議です。議題は三つです。最初は予算です。
```

3 文とも `です` で終わります。1 つの連なりに 1 件を、3 文目の語尾に出し、理由に連なりの長さ(4 文続けば 4)が出ます。

```text
今日は定例会議です。議題は三つで、最初は予算です。次に日程を決めます。
```

`です` `です` `ます` と続くので、指摘しません。語尾が一覧にない文(体言止め、`ですが。` のような助詞止め)や、終端の記号がない文は、連なりを切ります。段落が変わると数え直します。

直し方: 1 文を前の文と接続助詞でつなぐ、語順を入れ替える、状態を述べる文に変える、のいずれかで語尾を変えます。手順の並列や対句のように、そろえること自体が目的なら、そのままで構いません。

### `choppy_sentences`

短い文が、同じ段落に続けて並んでいる書き方です。

文の長さは、終端の記号を含め、空白とマスクされた部分(インラインコード、URL、リンク先)を除いた文字数です。強調の `*` は文字として数えます。次のどちらかを満たす文を、短い文と数えます。

- 22 字以下。
- 38 字以下で、節をつなぐ読点がない。節をつなぐ読点とは、接続の形(`て` `で` `し` `が` `けれど` `ので` `から` `ため` `ながら` `ものの` `ば` `たら` `なら` `と`)の直後の `、` または `，` です。

| ジャンル                         | 続く文の数 |
| -------------------------------- | ---------- |
| `general` `technical` `business` | 4 文以上   |
| `essay`                          | 5 文以上   |

エッセイは、短い文を意図して重ねることが多いので、1 文多く許します。

```text
朝に家を出た。電車は空いていた。席に座った。本を開いた。
```

4 文とも 22 字以下です。1 つの連なりに 1 件を、最初の文に出し、理由に連なりの文数が出ます。

```text
朝に家を出て、空いていた電車の席に座り、本を開いた。
```

直し方: 前提と、それに続く動作を、`〜て、` や `〜が、` でつないで 1 文にします。長い文と短い文を混ぜると、短い文が強調として働きます。

### `uniform_sentence_length`

文の長さがほとんど同じで、単調に読める文書です。

本文の、終端の記号で終わる文が 8 文以上あるとき、文の長さ(`choppy_sentences` と同じ数え方)の変動係数、つまり標準偏差を平均で割った値を調べます。次の値を下回ると指摘します。

| ジャンル                         | 変動係数  |
| -------------------------------- | --------- |
| `general` `technical` `business` | 0.25 未満 |
| `essay`                          | 0.2 未満  |

指摘は文書に 1 件で、最初の文を示します。理由に、変動係数、文の数、平均の長さが出ます。文が 8 文に満たない文書は、ばらつきを判断できないので調べません。

直し方: 結論は短く、理由や条件は長くするなど、内容に合わせて長さを変えます。手順書のように、型をそろえて書く文書なら、そのままで構いません。

## 立場

### `stance_ending`

文書の立場と、文末が食い違っている文です。重大度は `warn` です。呼び出しで `stance`(`advice`、`rule`、`explanation`)を指定したときだけ調べます。指定がなければ、このルールは動かず、`not_run` にも出ません。

数える文は `register` と同じく、本文とリストの項目の、終端の記号で終わる文です。語尾を、次の 4 種類に分けます。語尾は、先に挙げたものから順に調べます。

| 種類 | 語尾                                                                                                                                 |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 依頼 | `ください` `下さい` `てください` `してほしい` `お願いします`                                                                         |
| 勧め | `ましょう` `とよいでしょう` `とよいです` `といいです` `をおすすめします` `をお勧めします` `ことをおすすめします` `べきです` `べきだ` |
| 評価 | `重要` `大切` `大事` `不可欠` `必要` のあとに `です` `だ` `である` が付いたもの、`欠かせません`                                      |
| 動作 | 上のどれでもない、`ます` で終わる丁寧な動詞(`押します`、`開きます`)                                                                  |

動作のうち、読み手が行うことではないものは、動作と数えません。受け身(`れます` `られます`)、進行(`ています` `でいます`)、状態(`あります` `なります` `できます`、`が` `に` `も` `は` に続く `います`)です。

立場ごとに、次の種類の語尾が食い違いになります。

| `stance`      | 食い違いになる語尾               |
| ------------- | -------------------------------- |
| `advice`      | 動作                             |
| `rule`        | 勧め、評価                       |
| `explanation` | 勧め、依頼(文書の最後の文を除く) |

```text
画面を開きましょう。ボタンを押します。設定は記録されます。
```

`advice` では、`押します` が動作で、食い違いです。`開きましょう` は勧めで、`記録されます` は受け身なので、指摘しません。

```text
毎日保存します。週に一度は見直しましょう。手順の順番が大切です。
```

`rule` では、`見直しましょう`(勧め)と `大切です`(評価)が食い違いです。

```text
結果は三件でした。付録を見てください。差は小さいです。
```

`explanation` では、途中の `見てください` が食い違いです。文書の最後の文が依頼や勧めで終わるのは、読み手への案内として自然なので、指摘しません。

指摘の範囲は、語尾から終端の記号までです。理由に、語尾の種類と立場(`a recommendation in a rule` のように)と、語尾が出ます。

形態素解析を使わず語尾で判断するため、`入れます` のように `れます` で終わる能動の動詞は、受け身と区別できず、動作に数えません。

直し方: 文書の目的に合わせて、立場を 1 つに決め、語尾をそろえます。決まりの文書なら、勧めや評価を `〜します` `〜してください` の言い切りに直し、理由を述べる文は残します。意図して語尾を混ぜているなら、`stance` を指定せずに調べます。

## 言い回し

ここのルールは、語句や言い回しを、パッケージが持つ一覧と照らして調べます。どれも `info` の目安で、指摘をどう扱うかは書き手が判断します。読み手が困る誤りではないので、引用やセリフ、意図して使っている言い回しは、そのままで構いません。

読む行は、本文、見出し、リスト、表です。引用ブロック、コードブロック、インラインコード、URL、リンク先は読みません。インラインコードをはさんだ語句は、つながった語句とは見ません。一致した語句ごとに 1 件を、その語句の範囲に出します。

最初の 2 つは、既定で動きます。「短く言い換えても読み取れることが変わらない」と言える表現だけを一覧に入れているので、好みの問題ではないからです。残りの 4 つは、書き方の好みや調子の選び方にかかわるので、既定では動きません。

### `stock_phrase`

意味を足さずに、字数だけを増やしている決まり文句です。重大度は `info` で、既定で動きます。

一覧に入れるのは、各表現に、同じ意味の短い言い方があるものだけです。短くすると意味が変わる表現や、分野によっては普通の言葉として使う表現は、入れません。

| 表現                                                | 短い言い方                         |
| --------------------------------------------------- | ---------------------------------- |
| `まず最初に`                                        | `まず`                             |
| `一番最初`                                          | `最初`                             |
| `一番最後`                                          | `最後`                             |
| `必ず必要`                                          | `必要`                             |
| `あとで後悔` `後で後悔`                             | `後悔`                             |
| `違和感を感じる`                                    | `違和感がある`                     |
| `今現在`                                            | `現在`                             |
| `各〜ごと`(`各チームごと`)                          | `各チーム` か `チームごと`         |
| `返事を返す` `返事を返します` `返事を返した` など   | `返事する` `返事します` `返事した` |
| `頭痛が痛い`                                        | `頭が痛い`                         |
| `いかがでしたか` `いかがでしたでしょうか`(文頭のみ) | 削ります                           |
| `結論から言うと、`(文頭のみ)                        | 削ります                           |
| `〜という形になります` `〜という形です`(名詞の直後) | `〜になります` `〜です`            |

一覧に入れない表現の例として、顧客向けの敬語で定型として使う `となっております` があります。`です` より丁寧な言い方として使う分野があるので、一覧に入れていません。

一致の条件は、次のとおりです。

- `あとで後悔` は、`食べた後で後悔した` や `その後で後悔した` のように、動作のあとを指す `後で` を数えません。数えるのは、`やらないとあとで後悔します` のように、「あとになって」の意味で使うものです。漢字の `後` は、`最後で後悔` のように漢字に続くものも数えません。
- `各〜ごと` は、`各` と `ごと` のあいだが名詞だけのときに数えます。`各メンバーが月ごとに報告します` のように助詞をはさむ文は、`各` と `ごと` が別の語にかかるので、数えません。
- `いかがでしたか` と `結論から言うと、` は、文頭にあるときだけです。`旅行はいかがでしたか。` は、読み手への本当の問いなので数えません。
- `という形になります` と `という形です` は、直前が漢字かカタカナのときだけです。`分けるという形になります` のように動詞に続く文は、`分けるになります` にならないので数えません。

```text
まず最初に設定を開きます。各チームごとに結果を共有します。
```

`まず最初に` は `まず` と言い換えられ、`各チームごと` は `各` と `ごと` の一方で足ります。

指摘の範囲は、一致した語句です。理由に、短い言い方が出ます(`"まず最初に": "まず" says the same`)。削れる語句は `"結論から言うと、" can go`、`各〜ごと` は `say 各 or ごと, not both` です。

直し方: 短い言い方に直すか、語句を削ります。引用や、決まった言い回しを使う文書(顧客向けの定型文など)で意図して使っているなら、そのままで構いません。

### `translationese`

翻訳の言い回しをそのまま日本語に持ち込んだ書き方です。重大度は `info` で、既定で動きます。`stock_phrase` と同じ考え方で、各表現に同じ意味の短い言い方があるものだけを入れています。

| 表現                                              | 短い言い方                                                   |
| ------------------------------------------------- | ------------------------------------------------------------ |
| 名詞+`することができる`(`確認することができます`) | `できる`(`確認できます`)                                     |
| ほかの動詞+`ことができる`(`読むことができる`)     | 動詞の可能形(`読める`)                                       |
| 名詞+`することが可能です` `だ`                    | `できます` `できる`                                          |
| 名詞+`することが可能になる` `となる`              | `できるようになる`                                           |
| `することによって`                                | `することで`                                                 |
| 名詞+`を行う` `行います` `行った` など            | 名詞+`する` `します` `した`(`確認を行います` → `確認します`) |
| 名詞+`という点において`                           | `の点で`(`速度という点において` → `速度の点で`)              |
| 名詞+`することを可能にする`                       | `できるようにする`                                           |

一致の条件は、次のとおりです。

- `することができる` と `することが可能です` は、`する` の前が漢字かカタカナ 2 文字以上の名詞のときだけです。`愛する` のように 1 文字の語は、`愛できる` ではなく `愛せる` なので、`ことができる` の側で扱います。`運動をすることができる` のように `を` の直後に `する` が来る文も、`ことができる` の側です。
- `ことができる` は、動詞の終わりが `う` `く` `ぐ` `す` `つ` `ぬ` `ぶ` `む` `る` のときです。可能形は動詞ごとに違うので、理由には短い言い方を出しません(`"ことができ": the potential form of the verb says the same`)。
- `を行う` に当てはまる名詞は、`確認` `変更` `設定` `保存` `削除` `作成` `更新` `実行` `検討` `説明` `調査` `対応` `追加` `修正` です。
- `することが可能だった` は、過去の形に言い換えが合わなくなるので、数えません。

```text
設定を確認することができます。再起動することによって直ります。
```

`確認することができます` は `確認できます` に、`再起動することによって` は `再起動することで` に言い換えられます。

指摘の範囲は、一致した語句です。`することができる` では `することができ` の部分で、`を行う` では名詞から `行` の活用語尾までです。理由に、短い言い方が出ます(`"確認を行います": "確認します" says the same`)。`データの確認を行う` のように名詞に `の` が付く文は、`データを確認する` と助詞も直します。

直し方: 短い言い方に直します。法令や契約書のように、決まった言い回しを使う文書や、引用なら、そのままで構いません。

### `vague_buzzword`

具体的な内容を言わずに、流行の言葉で済ませている書き方です。重大度は `info` で、既定では動きません。

ある文書では、決まった意味で通じる言葉です。別の文書では、言いたいことをぼかす言葉になります。どちらが良いかは調子の選び方なので、読み手全員の負担にはなりません。そのため、設定の `rules` または引数の `rules` に `vague_buzzword` を入れたときだけ調べます。

| 言葉                                                                               | 数える形                                               |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `解像度`                                                                           | `解像度を上げる` `解像度が高い` など(比喩の使い方だけ) |
| `腹落ち` `肌感覚` `温度感` `爆速` `言語化` `ブラッシュアップ` `ゲームチェンジャー` | そのまま                                               |
| `熱量`                                                                             | `熱量を感じる` `熱量を込める` `熱量が伝わる` など      |
| `刺さる`                                                                           | `読者に刺さる` のように、人を表す語に続くもの          |
| `エモい`                                                                           | `エモい` `エモく` `エモさ`                             |
| `地に足のついた`                                                                   | `地に足の(が)ついた`                                   |
| `本質的な`                                                                         | そのまま                                               |
| `落とし込む`                                                                       | `落とし込む` `落とし込み` など                         |
| `寄り添う`                                                                         | `現場に寄り添う` のように、人や場を表す語に続くもの    |

`画面の解像度` `写真の解像度が低い` のように、画面や画像の細かさを言う `解像度` は数えません。`画面` `画像` `映像` `動画` `写真` `ディスプレイ` `モニター` `カメラ` `液晶` `パネル` `スキャナ` `プリンタ` `テレビ` `ピクセル` `4K` `8K` のどれかが、6 字以内の手前にあれば、本来の意味とみなします。

```text
課題の解像度を上げて、腹落ちするまで話す。
```

指摘の範囲は、一致した語句です。理由は、`a buzzword; say what it stands for` です。

直し方: その言葉が何を指すのかを、書き手の言葉で言い直します。`課題の解像度を上げる` なら、`課題を細かく分けて、原因を特定する` などです。決まった意味で共有している読み手向けの文書なら、そのままで構いません。

### `metaphor_verb`

ふつうの動作を、比喩の動詞で言っている書き方です。重大度は `info` で、既定では動きません。

比喩は文章の調子を作るので、使うかどうかは好みと読み手で決まります。`vague_buzzword` と同じく、`rules` に `metaphor_verb` を入れたときだけ調べます。本来の意味の使い方(`現場を回る` `布の手触りがよい`)は数えないよう、比喩になる目的語と組み合わせたものだけを一覧にしています。

| 比喩         | 数える形                                                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| 業務を回す   | `業務` `仕事` `案件` `組織` + `を回す` `が回る`                                                                |
| 時間を溶かす | `時間を溶かす` `時間が溶ける`                                                                                  |
| 合意を握る   | `合意` `方針` `認識` + `を握る`                                                                                |
| 機能が生える | `機能が生える` `機能を生やす`                                                                                  |
| 手触り       | `操作` `画面` `アプリ` `ツール` `サービス` `UI` `API` `使い` + `(の)手触り`                                    |
| じわじわ効く | `じわじわ(と)効く` など                                                                                        |
| 地味に効く   | `地味に効く` など                                                                                              |
| 背中を押す   | `決断` `挑戦` `導入` `判断` `行動` `成長` `ユーザー` `顧客` `読者` `部下` `チーム` `メンバー` + `の背中を押す` |
| 風通しがよい | `組織` `職場` `社内` `チーム` `会社` `部署` + `(の)風通し`                                                     |
| 棚卸し       | `課題` `業務` `タスク` `施策` `機能` + `を棚卸し`                                                              |
| 地雷を踏む   | `地雷を踏む` など                                                                                              |
| 炙り出す     | `課題` `問題` `原因` + `を炙り出す`(`あぶり出す` も)                                                           |

```text
会議が時間を溶かし、業務を回すのに苦労している。
```

指摘の範囲は、一致した語句です。理由は、`a metaphor; the plain verb may read clearer` です。

直し方: 平易な動詞に言い直します。`時間を溶かす` は `時間を使い切る`、`業務を回す` は `業務を続ける` などです。比喩で調子を出したいエッセイや読み物なら、そのままで構いません。

### `contrast_overuse`

`AではなくB` の対比が、文書のなかで何度も出てくる書き方です。重大度は `info` で、既定では動きません。

対比は便利な型ですが、続けると、ほとんどの文が「〜ではなく」を言い直すように読めます。どのくらいを多いとみなすかは、文書の種類や書き手の調子で変わるので、`rules` に `contrast_overuse` を入れたときだけ調べます。

数える形は、次の 4 つです。

- `ではなく`
- `だけでなく`(同じ文のあとに `も` があるもの)
- `わけではない` `わけではありません`
- `というより` `というよりは` `というよりも`

読む行(本文、見出し、リスト、表)のなかで、この 4 つの数を数えます。割る数は、`register` と同じ、本文とリストの項目のうち終端の記号で終わる文の数です。次の両方を満たすときに指摘します。

- 数が 3 以上。
- 1 文あたりの数が、次の値以上。

| ジャンル                     | 1 文あたりの数 |
| ---------------------------- | -------------- |
| `general` `business` `essay` | 0.05 以上      |
| `technical`                  | 0.08 以上      |

技術文書は、仕様や条件を「AではなくB」と区別して書くことが多いので、少し多くても許します。

指摘は文書に 1 件で、最初の対比を示します。理由に、数、文の数、1 文あたりの数が出ます(`4 contrast constructions in 20 sentences, 0.20 per sentence; 0.05 or more reads as a habit`)。

直し方: 主張を肯定の文で言い切れるものは、そうします。`速さではなく正確さを選ぶ` は、`正確さを選ぶ` で足ります。比較そのものが主題の文書なら、そのままで構いません。

### `emoji`

文章のなかの絵文字です。重大度は `info` で、既定では動きません。

絵文字は、くだけた調子を作ります。読み手や媒体によって、歓迎されることも、場にそぐわないこともあるので、`rules` に `emoji` を入れたときだけ調べます。

既定で絵文字の絵として表示される文字を、読む行から探します。Unicode の Emoji_Presentation に当たる文字(`🎉` `✅` `🚀`)と、Extended_Pictographic に当たる文字に絵文字用のバリエーションセレクタ(U+FE0F)が付いたもの(`✔️` `⚠️`)です。

`↔` `✔` `▶` `‼` `ℹ` `☑` `♥` `☺` のように、セレクタが付かないときは文字として表示される記号は、数えません。`©` `®` `™` も、文書では記号として使うので数えません。数字、`#`、`*` を枠で囲む絵文字(`1️⃣`)も、数えません。

肌の色の修飾が付いた並び(`👋🏽`)と、家族の絵文字のようにゼロ幅接合子(U+200D)でつないだ並びは、1 つの絵文字です。絵文字が続く並びは、1 件にまとめます。

```text
完了しました🎉🔥 次は🚀です。
```

2 件を指摘します(`🎉🔥` と `🚀`)。指摘の範囲は、絵文字の並びです。理由は、`an emoji sets a tone; "🎉🔥" may be left out` のように、並びを引用します。

直し方: 絵文字を外すか、言葉に言い直します。くだけた調子を選んでいる文書なら、そのままで構いません。
