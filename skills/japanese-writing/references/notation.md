# 表記のルール

`notation` チェックが報告する、表記の揺れと誤りの解説です。指摘ごとの `reference` は、このファイルの見出しを指します。見出しはルールの id そのものです。

## 基本の考え方

日本語の表記には、どちらも誤りではない流儀が複数あります。たとえば和文と英単語のあいだの空白は、入れる文書も入れない文書もあります。そこで、このチェックは特定の流儀を正解とみなしません。

- **規約を決めている場合**: 設定または呼び出しの引数で値を指定すると、文書全体がその値に従っているかを調べます。外れた箇所が 1 件ずつ指摘されます。
- **規約を決めていない場合**: 文書が使っている値を数え、多数派に合わない箇所だけを指摘します。2 種類以上が混ざっていない文書は、どちらの流儀でも指摘されません。多数派が同数のときは、先に現れた値を多数派とみなします。

規約の名前は、設定と引数で共通です。値は規約ごとに決まっていて、`document` を指定すると「文書自身に合わせる」(既定) になります。呼び出しの引数は設定より優先されます。

結果の `conventions` には、規約ごとに何に合わせたかが出ます。`source` は次のいずれかです。

| `source`   | 意味                                                     |
| ---------- | -------------------------------------------------------- |
| `argument` | 呼び出しの引数で指定された                               |
| `setting`  | 設定で指定された                                         |
| `document` | 指定がなく、文書の多数派で決まった(`value` に多数派の値) |
| `unset`    | 指定がなく、文書がその規約を使っていない                 |

ルールは `exclude_rules` で無効にできます。無効にしたルールの規約は、調べることも、`conventions` に値を出すこともありません。

どのルールも、次の箇所は読みません。

- コードブロック、インラインコード、URL、リンク先、HTML コメント、フロントマター
- 引用ブロック(他人の文章だからです)

見出し、リストの項目、表のセルは読みます。

## 和文と英数字のあいだの空白

### `latin_spacing`

和文と英単語、またはインラインコードのあいだに空白を入れるかどうかの規約です。

| 値         | 例                         |
| ---------- | -------------------------- |
| `spaced`   | `日本語 Python を使います` |
| `unspaced` | `日本語Pythonを使います`   |

`spaced` は半角空白が 1 つ以上あること、`unspaced` は隣り合っていることを指します。強調の `**` や `_`、リンクの角括弧は無いものとして扱うので、`**API**を` も `API` と `を` の境界です。

数えないもの:

- 数字だけの並び(`10月`、`3人`)は英単語ではありません。
- 英単語の直後が句読点のとき(`Python、`)は境界ではありません。
- 全角空白で区切った場合は、この規約の対象外です。`space_between_japanese` が扱います。
- 行をまたぐ並びは、改行を空白とはみなさず、境界にもしません。

直し方: 指摘の箇所を、文書の他の部分か、決めた値に合わせます。多数派に合わせる指摘が多すぎるときは、規約を設定で決めたほうが結果は読みやすくなります。

### `unit_spacing`

数値と、半角英字の単位のあいだに空白を入れるかどうかの規約です。

| 値         | 例       |
| ---------- | -------- |
| `spaced`   | `100 MB` |
| `unspaced` | `100MB`  |

単位は、パッケージが持つ次の一覧に限ります。

`B` `KB` `MB` `GB` `TB` `PB` `KiB` `MiB` `GiB` `TiB` `bps` `Kbps` `Mbps` `Gbps` `Hz` `kHz` `MHz` `GHz` `ms` `us` `µs` `ns` `px` `pt` `em` `rem` `dpi` `mm` `cm` `m` `km` `mg` `g` `kg` `mL` `L` `W` `kW` `V` `mAh`

数えないもの:

- 英数字、`.`、`_`、`-` の直後の数字は、数値とはみなしません(`v1.2m`、`x86B`、`abc10MB`)。
- 単位の直後に英数字が続くときは、別の語です(`10 meters`)。
- `%`、`°`、`℃` は対象外です。

直し方: 単位の前の空白を、文書全体で同じ形にそろえます。

### `space_between_japanese`

和文の文字と文字のあいだに入った空白です。半角空白でも全角空白でも指摘します。

```text
日本 語の文章
```

数えないもの:

- 行頭の字下げ(全角空白)。文字と文字のあいだではないからです。
- 和文と英単語のあいだの空白は `latin_spacing` が扱います。

直し方: 空白を削除します。語を区切る目的で入れていた場合は、表記を見直すか、中黒や句読点を使います。

### `space_around_punctuation`

`、` `。` `，` `．` の直前の空白と、同じ行で文が続くときの直後の空白です。

```text
日本語 、続きます。 次の文です。
```

数えないもの:

- 行末の空白。Markdown では強制改行の指定なので、本文の空白ではありません。
- 半角の `,` と `.`。英文の書き方は対象外です。

直し方: 空白を削除します。

### `space_inside_brackets`

開き括弧の直後と、閉じ括弧の直前の空白です。対象は `「` `『` `（` `【` `〔` `〈` `《` と、それに対応する閉じ括弧です。

```text
「 日本語 」と書く
```

数えないもの:

- 括弧の外側の空白。
- 開き括弧の直後が行末のとき(行末の空白は強制改行の指定です)。

直し方: 括弧の内側の空白を削除します。

## 文字の幅

### `alnum_width`

英字と数字を半角で書くか、全角で書くかの規約です。

| 値          | 例                   |
| ----------- | -------------------- |
| `halfwidth` | `2024年のAPI`        |
| `fullwidth` | `２０２４年のＡＰＩ` |

全角の英数字は、どこにあっても数えます。半角の英数字は、和文の文字が前後 2 文字以内にあるときだけ数えます(空白と、強調やリンクの記号は文字に数えません)。英文や、和文から離れたコード風の語は、この規約の対象外です。インラインコードも読みません。

直し方: 幅を文書全体でそろえます。どちらにそろえるかは、文書や組織の規約で決めます。

### `bracket_width`

和文を囲む丸括弧の幅の規約です。

| 値          | 例           |
| ----------- | ------------ |
| `fullwidth` | `（日本語）` |
| `halfwidth` | `(日本語)`   |

同じ行の中で、中に別の丸括弧がなく、和文の文字を含む組だけを数えます。`(S)` や `(TM)` のようなアクセスキーや記号、`(1)` のような番号は和文を含まないので数えません。指摘の範囲は括弧を含む組全体です。

直し方: 括弧の幅を文書全体でそろえます。

### `halfwidth_katakana`

半角カタカナ(とその濁点、半濁点、句読点)です。規約ではなく、常に指摘します。

```text
ﾃｽﾄ → テスト
```

理由には、元の文字列と全角にした形が出ます。長い並びは先頭の 20 文字までです。

直し方: 全角にします。機械的な変換は、Unicode の NFKC 正規化と同じ結果です。

## 句読点

### `punctuation`

句点と読点の組み合わせの規約です。

| 値             | 読点 | 句点 | 例                   |
| -------------- | ---- | ---- | -------------------- |
| `ten_maru`     | `、` | `。` | `彼は、そう言った。` |
| `comma_period` | `，` | `．` | `彼は，そう言った．` |
| `comma_maru`   | `，` | `。` | `彼は，そう言った。` |

数えないもの:

- 数字にはさまれた `．` と `，`(`３．１４`、`１，０００`)は、小数点や桁区切りです。
- 半角の `,` と `.` は対象外です。

指定がないときは、読点と句点を別々に数え、それぞれの多数派と合わない記号を指摘します。`conventions` に値が出るのは、読点と句点の多数派をどちらも満たす値がちょうど 1 つあるときだけです。たとえば `、` と `。` が多数派なら `ten_maru` になります。`。` しか使っていない文書は `ten_maru` にも `comma_maru` にも合うので、値は決まらず `unset` のままです。`、` と `．` のように、どの値にも当てはまらない組み合わせも `unset` ですが、少数派の記号は指摘します。

直し方: 読点と句点を、文書全体で 1 つの値にそろえます。

## 引用符

### `quotes`

和文を囲む引用符の規約です。

| 値       | 例                               |
| -------- | -------------------------------- |
| `corner` | `担当者は「確認します」と答えた` |
| `double` | `担当者は“確認します”と答えた`   |

`double` には、曲線の引用符(`“` と `”`)と、半角の `"` の組が入ります。同じ行の中で対になり、中に和文の文字を含む組だけを数えます。指摘の範囲は引用符を含む組全体です。

数えないもの:

- `『』` は、入れ子の引用や書名に使うので、どの値にも数えません。`「…『…』…」` は、外側の `「」` だけを数えます。
- 中に和文の文字がない組(`"OK"`、`「API」`)。
- 閉じていない記号と、行をまたぐ組。半角の `"` は、行の中で出てきた順に 2 つずつ対にします。
- 中に同じ種類の記号が入る組。`「…「…」…」` では内側の組だけを数えます。
- 引用ブロック(他人の文章だからです)。

直し方: 引用符を、文書全体で 1 つの値にそろえます。コード風の語を半角の `"` で囲んでいる場合は、インラインコードにすると対象から外れます。

## 数と語の表記

### `range_mark`

2 つの数のあいだに置いて、範囲を表す記号の規約です。

| 値                | 記号                        | 例       |
| ----------------- | --------------------------- | -------- |
| `wave_dash`       | `〜`(U+301C 波ダッシュ)     | `3〜5日` |
| `fullwidth_tilde` | `～`(U+FF5E 全角チルダ)     | `3～5日` |
| `hyphen`          | `-` または `–`(en ダッシュ) | `3-5日`  |

`〜` と `～` は、多くのフォントで見分けがつきません。そのため、2 つが混ざっていても気づきにくく、検索や置換、機械処理で別の文字として扱われてはじめて問題になります。

数えるのは、数値、記号、数値の順に並んだ箇所です。数値は半角でも全角でもよく、小数点を含められます。最初の数値の後ろには、3 文字までの単位(`3時〜5時`、`10%〜20%`、`10MB〜20MB`)と、空白を置けます。指摘の範囲は記号 1 文字です。

数えないもの:

- 半角の `~` は、どの値でもありません。
- ハイフンは、ちょうど 2 つの数をつなぐときだけ数えます。日付(`2026-11-26`)や電話番号(`03-1234-5678`)のように 3 つ以上の数がつながる場合は、範囲ではありません。
- ハイフンでつないだ数の外側に英字が接しているとき(`x86-64`、`v1-2`)は、型番や版番号です。`ISO-8601` のように前に数値がないものも数えません。

直し方: 記号を、文書全体で 1 つの値にそろえます。機械処理を前提にする文書では、`hyphen` が扱いやすいことがあります。

### `long_vowel`

外来語の語末の長音「ー」を残すか、略すかの規約です。

| 値     | 例                     |
| ------ | ---------------------- |
| `keep` | `サーバー`、`ユーザー` |
| `drop` | `サーバ`、`ユーザ`     |

対象は、パッケージが両方の形を持つ次の語に限ります。

`コンピューター` `ユーザー` `サーバー` `プリンター` `フォルダー` `ブラウザー` `パラメーター` `エディター` `ドライバー` `スキャナー` `マネージャー` `コンテナー` `ヘッダー` `フッター` `フィルター` `アダプター` `モニター` `センサー` `コントローラー` `プロバイダー` `インストーラー` `ビューアー` `プレイヤー` `レンダラー` `パーサー` `ハンドラー` `ルーター` `クラスター` `バッファー` `カウンター` `イテレーター` `ジェネレーター` `コンストラクター` `ポインター` `リスナー` `ローダー` `リーダー` `ライター` `メンバー` `オーナー` `メモリー` `カテゴリー` `ディレクトリー` `ライブラリー` `エントリー` `セキュリティー` `プロパティー` `ユーティリティー` `リポジトリー` `クエリー` `バッテリー`

語がカタカナの並びとして単独で現れたときだけ数えます。指摘の理由には、もう一方の形が出ます。範囲は語全体です。

数えないもの:

- 語が、より長いカタカナの並びの一部のとき(`サーバーサイド`、`メモリーカード`、`ユーザビリティ`)。
- 一覧にない語。どちらの形で書いても指摘しません。

中黒(`・`)は語の区切りとして読むので、`ユーザー・サーバー` は 2 語として、それぞれ数えます。

直し方: 語末の長音を、文書全体で 1 つの値にそろえます。組織の用語集や、書き方の規約がある場合は、それに従います。

### `counter_ka`

「3か月」のように、数に続く「か」の書き方の規約です。

| 値         | 文字       | 例               |
| ---------- | ---------- | ---------------- |
| `hiragana` | `か`       | `3か月`、`5か所` |
| `small_ke` | `ヶ`、`ケ` | `3ヶ月`、`5ケ所` |
| `katakana` | `カ`、`ヵ` | `3カ月`、`5カ所` |

数えるのは、数に続く「か」「ヶ」「ケ」「カ」「ヵ」のうち、そのあとに `月` `所` `国` `条` `年` が続くものです。数は、半角または全角の数字、漢数字(`一` から `九`、`十` `百` `千`)、`何` `数` `幾` です(`何か所`、`数カ月`)。指摘の範囲は「か」にあたる 1 文字です。

数えないもの:

- 後ろに上の名詞が続かない「ケ」。`3ケ` が「3個」の意味のときは、この規約の対象外です。
- 数に続かない「か」(`いつか月を見る`)。

直し方: 「か」の書き方を、文書全体で 1 つの値にそろえます。
